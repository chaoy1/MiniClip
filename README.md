# MiniClip

## 一句话定义

> MiniClip 是一个不抢焦点、通过键盘快速选择历史文本并粘贴到当前输入位置的 Windows 极简剪贴板工具。

这句话来自项目规划书第三十二节，是产品的唯一定位。MiniClip 交互上像输入法候选框：常驻托盘，按下快捷键后在文字光标附近显示候选框，用 ↑ ↓ 选择、Enter 粘贴、Esc 关闭；候选框全程不获得键盘焦点，你原来正在打字的窗口保持激活。无法读取文字光标时，改用当前焦点控件的位置。

## 系统要求

| 项 | 要求 |
| --- | --- |
| 操作系统 | Windows 10 / 11（64 位） |
| 运行时 | **.NET 10 桌面运行时**（.NET Desktop Runtime）：安装包已内置，不必自己装；绿色发布包需要先安装 |
| 磁盘占用 | 绿色发布包程序本体约 **0.55 MB**；安装包 **48.8 MB**，安装后程序目录约 **155.7 MB**（含 .NET 10 桌面运行时） |
| 内存占用 | 常驻约 **58 MB**（实测值） |
| 网络 | **不需要，且从不联网** |

**用安装包安装的话，运行时不需要你操心。** 安装包是自包含发布，已经把 .NET 10 桌面运行时打了进去，装完就能用，不用另外下载任何东西。下面这段说明只针对自己下载绿色发布包的情况；**绿色发布包没有内置运行时**，目标机器必须先装一次。

**关于 .NET 10 桌面运行时**——绿色发布包唯一的额外前提，需要说清楚：

- 要装的是 **Desktop Runtime**，不是普通的 .NET Runtime。普通运行时只够跑控制台程序，WPF 桌面程序必须用桌面版。下载地址：[.NET 10 下载页](https://dotnet.microsoft.com/en-us/download/dotnet/10.0)，选 “.NET Desktop Runtime 10.x — Windows x64”。
- 运行时的安装程序只有几十 MB，装一次即可；同机器上所有 .NET 10 桌面程序共用，不必为 MiniClip 单独准备。
- 没装的表现：双击没反应，或弹出提示缺少运行时的对话框。
- 怎么确认装没装：在命令行跑 `dotnet --list-runtimes`，能看到 `Microsoft.WindowsDesktop.App 10.x` 就说明够了；或在“设置 → 应用 → 已安装的应用”里找 “Microsoft Windows Desktop Runtime 10”。
- **绿色发布包故意不带运行时**，这样程序本体只有 0.55 MB。安装包走的是另一条路：自包含发布（269 个文件、约 155.7 MB）再用 Inno Setup 压缩成 **48.8 MB** 的安装程序，代价是安装包体积，换来的是“对方不用装任何东西”。把约 140 MB 的 .NET 运行时塞进绿色发布目录只换来“对方不用装”，体积涨约 270 倍，而运行时的内存和启动开销一分没省——框架依赖实测约 58 MB / 226 ms，自包含实测约 60 MB / 257 ms。完整的实测取舍见 [docs/BUILD.md](docs/BUILD.md)。

## 它解决什么问题

日常复制粘贴有一个具体的痛点：复制过的东西过一会儿就找不回来了。

规划书第四节的场景：

```
复制：

docker compose up -d

过了一会又复制：

SELECT * FROM users;
```

`git status`、`SELECT * FROM users;` 这类内容会被反复用，但系统剪贴板只保留最后一次。传统做法是回到原处重新找、重新复制、切回窗口、粘贴；MiniClip 把这一步变成按一次快捷键。

它不做剪贴板管理器。它只做一件事：把你刚才复制过的文本，用键盘选回来，写进你正在输入的位置。

## 日常使用

```
Ctrl + C          正常复制，MiniClip 自动记录
Alt + V           呼出候选框（默认快捷键，可改）
↑ / ↓             移动选中项
Enter             把选中文本写入系统剪贴板，并向原窗口发送 Ctrl + V
Esc               关闭候选框
```

三点需要说清楚：

- **候选框不抢焦点**。这是产品的核心设计，也是它和绝大多数剪贴板工具的区别。候选框打开期间，你原来正在打字的输入框仍然是激活状态，光标还在原处；↑ ↓ Enter Esc 由 MiniClip 临时接管，其他按键正常交给原程序。实测证据见 [docs/VERIFICATION.md](docs/VERIFICATION.md)。
- **粘贴一次**。Enter 之后 MiniClip 先核对目标窗口有没有变；如果在你选择期间切了窗口，它不粘贴，直接关掉候选框。系统剪贴板会保留所选文本，所以手动 Ctrl + V 也能用。
- **避免粘错内容**。MiniClip 写入选中文本后会短暂等待目标程序处理剪贴板更新；若这期间另一项复制覆盖了剪贴板，就取消自动粘贴，并保留那次新复制。
- **再按一次 Alt + V 只关闭候选框**，不会叠出第二个框。历史为空时候选框显示空状态，Enter 不执行任何粘贴。
- **列表会滚动**。候选框最多显示 5 行，历史最多保留 100 条；旧记录在上，新记录在下，默认选中最下方的最新记录。超过 5 条时靠 ↑ ↓ 滚动，选中行会保持在可视区域。
- **外观可切换**。右键托盘图标，展开“外观设置”，选择“浅色”“深色”或“跟随系统”；跟随系统时，Windows 应用或系统外观设为深色、或夜间模式开启，弹窗使用深色背景。选择保存在 `settings.json`，弹窗本身没有底部提示栏。

## 功能范围（V1）

MiniClip V1 只做这些：

| 能力 | 说明 |
| --- | --- |
| 纯文本监听 | 读取 Windows 标准文本格式及常见 `text/plain`、`Plain Text` 注册格式；图片、文件、HTML、富文本一律忽略 |
| 最近最多 100 条 | 弹窗从上到下由旧到新，最新在最下方；文本总量最多 500,000 字符，长文本较多时可能少于 100 条 |
| 精确去重 | 与最新记录完全相同的内容不新增；复制较早的内容则把它移到最新位置 |
| JSON 保存 | 每次历史变更后立即落盘，退出保存只是兜底 |
| 快捷键呼出 | 默认 Alt + V，可在设置里更换 |
| 不抢焦点 | `WS_EX_NOACTIVATE` + `SWP_NOACTIVATE` |
| ↑ ↓ 选择 | 到头不回绕；超过 5 条时列表滚动，选中行始终可见 |
| Enter 粘贴 | 写入剪贴板后注入 Ctrl + V |
| Esc 关闭 | 立即恢复正常输入 |
| 系统托盘 | 紧凑短菜单显示状态、清空历史、外观设置子菜单、设置、退出；设置页管理快捷键、开机启动和历史文件位置 |
| 清空历史 | 确认后同时清空内存与磁盘；当前系统剪贴板不变 |

如果启动时历史文件无法读取，MiniClip 会暂停写入，避免覆盖原文件。菜单会出现“清空异常历史…”；确认删除后可重新记录。删除失败会提示，原文件仍留在磁盘上，也可从设置页打开历史文件位置检查。

### 不做什么

规划书第三节把这些明确列为非项目目标，并且强调原则是：

> 如果一个功能不能直接提升“快速选择历史文本并粘贴”的体验，则暂时不加入 V1。

所以 V1 没有，也不打算有：

图片剪贴板 · 文件剪贴板 · HTML 富文本 · 云同步 · 用户登录 · 多设备同步 · OCR · AI 功能 · 剪贴板标签 · 收藏夹 · 剪贴板分类 · 复杂搜索 · 插件系统 · Web 管理后台 · 剪贴板管理类多级菜单 · 复杂设置页面

设置页仅收纳快捷键、开机启动、历史条数、打开历史文件位置及本机明文说明。它不提供额外的剪贴板管理功能。

## 快捷键

默认是 **Alt + V**。可以改：托盘图标双击，或托盘右键菜单里的“设置…”。在设置页点击快捷键输入框，再按下想用的组合键。

MiniClip 会拒绝这些组合（`HotkeyGesture.IsValid`）：

| 规则 | 原因 | 界面上会看到 |
| --- | --- | --- |
| 必须包含 Ctrl / Alt / Shift / Win 中至少一个 | 否则会挡住正常打字 | “全局快捷键至少需要 Ctrl、Alt 或 Shift 中的一个” |
| 不能只用 Shift | 只用 Shift 的组合会影响正常打字 | “只用 Shift 的组合会影响正常打字” |
| 不能只用 Win | Win + 单键和系统快捷键冲突 | “Win 加单键会和系统快捷键冲突” |
| 不能是 Windows 保留组合 | Alt+F4 / Alt+Tab / Alt+Esc / Alt+Space / Ctrl+Esc / Ctrl+Alt+Delete / Ctrl+Alt+Esc / Ctrl+Shift+Escape / Win+L / Win+D / Win+Tab | “这个组合被 Windows 保留，请换一个” |
| 键必须是 A–Z、0–9、F1–F24 或具名键 | 其他虚拟键码收不到 | “这个按键不能用作全局快捷键” |

修饰键按集合比较，顺序无关；多加一个修饰键就重新可用（例如 Ctrl+Alt+Shift+Delete 允许）。

**一个诚实的说明**：注册全局快捷键的权力在 Windows 手里。一个组合可能完全合法，但已经被别的程序占用了。这时 MiniClip 不会假装能用：托盘状态行显示“`<组合键>` 已被其他程序占用”，并显示一次黑白提示；设置对话框里点“保存”会留在原地显示失败原因，让你直接换一个。占用状态是别的程序造成的，MiniClip 无法读取是谁占用的。

## 历史与隐私

来自规划书第二十七节，不做任何软化：

- 历史以**本机明文 JSON** 保存。数据放在哪里取决于安装方式，两种布局都存在：

  | 情况 | 数据目录 |
  | --- | --- |
  | 用安装包安装（安装目录里有标记文件 `MiniClip.portable`） | `<安装目录>\data\`，例如 `D:\Apps\MiniClip\data\` |
  | 绿色发布包，或从 `bin\` 直接运行（没有标记文件） | `%LOCALAPPDATA%\MiniClip\` |
  | 有标记文件但安装目录不可写（例如普通用户装进 `C:\Program Files`） | 回退到 `%LOCALAPPDATA%\MiniClip\`，并在托盘提示「安装目录不可写，历史已改存到用户数据目录」 |

  **用安装包安装的版本，历史、设置和日志都放在安装目录下的 `data\` 里**，不写 C 盘的用户数据目录，卸载时随之一起删除；这就是“卸载不留痕迹”的实现方式。文件名在两种布局下相同，历史文件都叫 `history.json`，是纯字符串数组，可以直接用记事本打开看：

  ```json
  [
    "SELECT * FROM users;",
    "git status",
    "docker compose up -d"
  ]
  ```

  序列化器用的是 `JavaScriptEncoder.UnsafeRelaxedJsonEscaping`，所以双引号、`&`、`<` 和中文都以字面量落盘，不会出现 `\u0022` / `\u0026` 这种转义汤（换行仍是 `\r\n`、emoji 仍是 `\uD83D\uDE42` 代理对，那是 JSON 语法本身的要求）。实测：复制 `he said "hi" & <b> and 中文 ok` 之后文件里就是

  ```json
  [
    "he said \"hi\" & <b> and 中文 ok"
  ]
  ```

  复核方式与三种编码器的对照测量见 [docs/VERIFICATION.md](docs/VERIFICATION.md) 的“曾经报错的缺陷”第 4 条。

- **只在本机**。不联网、不上传服务器、不做云同步、没有遥测。日志不写剪贴板原文，连截断的原文都不写，只记录条数、状态和结果。
- **不做密码自动识别**，也不按来源程序排除。密码管理器自动复制的密码有可能被记录下来——这是已知问题，V1 不解决。第一次运行时会显示一次黑白提示，明确告诉你历史以明文存在本机。
- **自动清理**。历史只保留最近 100 条，并受 500,000 字符总量限制；诊断日志保留最近 7 天，单文件最多 1 MB，日志目录总量最多 10 MB。清理只处理诊断日志，不删除历史或设置。
- 托盘的**清空历史**会先显示确认窗口；确认后同时删除内存里的列表和磁盘上的 `history.json`，重启后不会恢复。它**不等同于安全擦除磁盘数据**。
- 清空历史只删 MiniClip 的历史记录，**不动当前 Windows 剪贴板**。
- 历史文件损坏时不会静默覆盖：原文件被改名保留为 `history.corrupt-<时间戳>.json`，MiniClip 以空历史启动并在托盘说明。

## 已知限制

| 限制 | 具体表现 |
| --- | --- |
| 管理员窗口收不到粘贴 | 普通权限运行的 MiniClip 无法向以管理员身份运行的程序注入按键。MiniClip 会先检测目标完整性级别，提示“目标窗口以管理员身份运行，请手动粘贴”，文本已经放进剪贴板。V1 不自动提权。 |
| 部分应用无法提供文字光标坐标 | MiniClip 依次尝试 Win32 光标、MSAA 无障碍光标和 UI Automation 文本选区；应用未提供有效坐标时，弹窗贴近当前焦点控件或窗口。不会依照鼠标位置定位。 |

Typora 等多进程编辑器可能由渲染进程提供 UI Automation 坐标，也可能通过 MSAA 暴露自绘光标。MiniClip 会校验应用与坐标范围，拒绝窗口原点等可疑位置；若提供者返回较慢，候选框打开后仍可短时间内重新定位。诊断日志只记录定位来源、坐标和耗时，不记录文档内容。
| 部分控件仍然可能拒绝 | 某些自绘控件、游戏、安全桌面不接受注入的 Ctrl + V。这类情况按“不承诺任何文本框均可用”处理，需要逐个记录。 |
| 内存占用高于规划书目标 | 规划书第二十六节写的是“尽量 < 50 MB”，这是**目标值**。本次 Release 常驻进程的单次空闲读数约为工作集 57 MB、私有内存 14 MB；按工作集口径仍高于目标。自检进程的内存读数包含多个 WPF 测试窗口，不能当作常驻占用。较早版本的重复测量及口径说明见 [docs/VERIFICATION.md](docs/VERIFICATION.md)。 |
| 同时只能运行一个实例 | 第二个实例会直接退出，不会和第一个抢快捷键、历史和剪贴板通知。 |

> 候选框列表可滚动：`PopupWindow.xaml` 中的 `ListScroller` 包住列表，选中变化时会把对应行滚入视口。当前自检覆盖 100 条记录和 5 行视口。较早的 30 条、8 行数据见 [docs/VERIFICATION.md](docs/VERIFICATION.md)，仅供历史对照。

MiniClip 提供包含 .NET 10 运行时的安装包（**48.8 MB**），**推荐用它安装**：装完即可运行，目标机器不用自己准备 .NET 运行时。安装向导始终显示目录选择页，可自选任意有写入权限的位置，附加选项里有“开机自动启动 MiniClip”和“创建桌面快捷方式”（两者默认都不勾选）。

数据跟着安装目录走，卸载的差别因此很大：

- **通过安装包安装**：数据在 `<安装目录>\data\`。卸载会删除安装文件、整个 `data\`（历史、设置、日志）、开机启动的注册表值及 Windows 启动管理器里的对应状态；`%LOCALAPPDATA%\MiniClip` 若存在也会一并清掉（照顾旧版本或手工拷贝的安装）。卸载后不留 MiniClip 数据。
- **绿色发布包**：没有卸载器。删掉发布文件只是删掉程序，数据仍在 `%LOCALAPPDATA%\MiniClip\`，**必须手动删除**；开机启动值也要在设置里关掉或手动删除。

详情及构建方法见 [docs/BUILD.md](docs/BUILD.md)。在没有开发环境的干净 Windows 机器上仍需复核安装、启动和完整卸载流程。
